# Mori 视觉与交互升级

当前入口已切换为 `src/app/ProductApp.tsx`，旧低保真 App/Screen 文件仅作第一批历史参考，不再由入口导入。

## 实际画面

- 暖木桌面、石墨色挂灯、显示器、逐个建模的键帽、鼠标、旋钮、盆栽与本子；使用 Three.js / React Three Fiber 实时渲染。
- 挂灯可通过射线拾取悬停/点击；点击触发 GSAP 2.65 秒镜头位置、注视点与 FOV 同步推进。HTML 屏幕只在镜头到位后淡入。
- 挂灯与显示器的 DOM 界面由 3D 世界坐标投影对齐，未使用整页 SVG 图片。挂灯负责简短反馈和机器人，显示器承担详细活动画面。
- 原始 SVG 保留游戏入口、开始/返回、暂停/退出/存档的结构，其灰色占位视觉已退出主页面。
- 六类机器人表情共享反馈映射；GSAP 控制眨眼、视线与弹性入场。灯条实现呼吸、暖光流动、两侧向中间聚拢。
- 游戏使用实时鼠标位置或键盘方向键；目标需停留达标，轨迹累计跟随。明确标注鼠标互动，不伪装成摄像头识别。
- 调试控制默认不挂载，按 D 或右下角设置按钮展开。

## 使用的技能与边界

- frontend-skill：全画布产品主体、低干扰导航、单一视觉重点、克制的暖色与绿色情绪体系。
- gsap-react、gsap-core、gsap-timeline：React 生命周期内的动画清理、镜头同步时间线、状态过渡与眨眼。
- img2threejs：实际阅读完整技能和 validation_rubric，进行输入适用性审查。现有 SVG 是界面总览，缺少可重建的单物体形体参考，因此未运行图片重建/相似度门禁；当前为原创程序化概念模型，不宣称参考图高保真重建。
- 环境无独立的 React Three Fiber 专用 Skill；使用真实 R3F、drei、Three.js 包与本地类型/API 完成场景。

## 视觉迭代依据

实际截图发现薄桌垫圆角超过厚度的一半，几何体膨胀遮住键盘。限制圆角后，键盘鼠标完整可见。前视屏幕边缘出现壁纸漏边，修正镜头注视方向与投影矩形。挂灯前面板改为圆角 Shape，避免薄 RoundedBox 的几何失真。短窗口去除固定最小高度，避免整体滚动。

## 当前范围

### 摄像头快速排查（本轮实测）

最终保留原 RAF 调度及新增的诊断指标。视频帧回调试验没有改善实测 FPS，且模拟视频回归出现首帧未检测，因此已撤回该试验。使用 debugging-and-error-recovery 技能依据原始失败信息定位这一增量回归。

Chrome 真实摄像头和本地模型成功，持续返回单人脸及 478 个关键点。视频源约 29.4 FPS，而原 requestAnimationFrame 检测调度约 1 FPS，单帧约 33 ms、P95 49.1 ms。改用 requestVideoFrameCallback（不支持时回退 RAF，保留 15 FPS 上限）后，本次会话仍约 1 FPS，视频源仍约 29.4 FPS，单帧约 44.5 ms、P95 58.4 ms。因此仅确定检测回调调度明显受限，尚不能认定具体的浏览器节流原因，也不能宣称性能问题已解决。未增加 Worker 或继续扩大优化范围。实测结束已停止并释放摄像头。主游戏保持鼠标/键盘输入，不受预检低帧率阻塞。

这是可展示、可操作的实时 3D 产品 Demo。主游戏目前由鼠标/键盘驱动；MediaPipe 保留为独立预检，不阻塞视觉体验。自然坐姿校准、真实动作判定及物理隐私开关尚未合入主游戏。模型属于程序化风格化表达，并非制造级外观模型。
