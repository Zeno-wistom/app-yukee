## 二、环境星光

旧问题可从代码直接证实：旧 `.moon-energy/.moon-attract` 属于船体 `.moon-bob` 子组，局部出生点为 x=270/370、y=150..168，并用 CSS 在附近振荡。全展开时局部位移趋近零，光点聚在帆面，缺少跨环境空间的完整旅程。并非仅仅被小容器裁掉。

新 `MoonFireflies.tsx` 是场景根 SVG 的直接子层，与船体缩放组互为独立层。`moonFireflyField.ts` 管理 28 枚粒子，出生区覆盖夜空、左右树林、城堡外侧与河流上方，避开月面及甲板。仅使用现有游戏 RAF 写 SVG 属性，不为每个粒子触发 React 更新。

环境浮动 → 按展开程度错峰启程 → 沿三次贝塞尔曲线进入对应帆面 → 柔和停留蓄光 → 真实次数增加后储存到船灯 → 淡出回到环境出生区。

目标通过 SVG 当前变换矩阵取得，自动包含缩放、双翼开合、浮动、航程变化。不是写死放大前的帆面屏幕坐标。每枚粒子的尺寸、颜色、相位、弯曲方向与时长有差异。

只有原动作会话的真实次数增加才触发储存奖励、船灯高亮、进度星飞入和少量向外扩散；展开保持不加分。原五次完成后的月光路径、庆祝和完成页继续使用。

手动暂停沿用原会话 RAF 门控；身体丢失/恢复阶段也不推进粒子时钟。恢复时间步限制为 50ms，不补播暂停期间的行程。减少动态偏好使用静态环境星光。
