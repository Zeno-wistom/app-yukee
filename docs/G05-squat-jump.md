## v2 更新

### 1. 动作检测修复（`src/vision/squatPose.ts`）
真人反馈：浅蹲难通过、校准第二步卡住、游戏内释放不稳。排查到的原因与修改：

| 环节 | v1 问题 | v2 修改 |
| --- | --- | --- |
| 肩点 | 可见度门槛 0.65；推理帧过期 250ms 即视为丢失 | 门槛 0.5（MediaPipe 正常可见时 >0.9）；校准 400ms、游戏 350ms 才算过期 |
| 校准缓冲 | 任一帧缺点就清空当前阶段、站立进度归零 | 掉帧 <0.6 秒保留进度 |
| 第 1 步站直 | 晃动按最大-最小值算，超限整段重来 | 按 p10–p90 范围、限值 max(4px, 0.07 W0)，超限只保留最近 30% 继续计时 |
| 第 2 步浅蹲（卡住主因） | 要求 0.5 秒内 q 变化 ≤0.04 W0 才算「停住」，蹲位的自然抖动与 MediaPipe 噪声经常超出；蹲下立刻站起不算 | 两种方式都能通过：①蹲到黄线停约 0.35 秒（容差 max(0.05 W0, 30% 当前下降)）；②蹲下→站起一个来回（在蹲位 ≥0.25 秒），幅度取蹲位 q 的 80 分位 ×0.85 |
| 第 2 步最小下降 | max(12px, 6×抖动, 0.08 W0)，嘈杂摄像头会要求很深 | max(8px, 4×抖动, 0.06 W0)，封顶 0.14 W0；预览里画出黄色目标线 |
| 第 2 步检查 | 与游戏同样严格 | 校准用宽松阈值：肩宽 0.72–1.35、横移 0.4 W0、侧倾 15° |
| 第 3 步站回 | u ≤0.2 稳定 400ms；人前后挪动后回不到原基线会一直卡住 | u ≤0.35 稳定 300ms；2.5 秒仍未回到且已稳定 0.6 秒、u<0.7 → 以当前站姿为新基线 |
| 游戏进入蓄力 | u ≥0.65 稳定 300ms，确认前的时间不计入蓄力 | u ≥0.5 稳定 100ms，确认等待计入蓄力（`enteredDownSec`） |
| 游戏释放 | 必须回到 u ≤0.25 稳定 220ms；基线漂移后永远到不了 → 不起跳 | 站立基线在站立区缓慢自适应（τ 2.5 秒，±0.6A）；u ≤0.3 稳定 120ms 释放；或已从峰值回落 ≥0.45A、u ≤0.55 且 250ms 内稳定 → 也释放并把基线挪到这里 |
| 检查项 | 蓄力中单帧失败就取消本轮 | 失败需持续 0.3 秒才取消；肩宽 0.75–1.3、横移 0.35 W0、侧倾 12°、两肩差 ≤0.45A |

**调试开关**：URL 加 `?g05debug=1`，或在 G05 校准 / 游戏页按 **D**（记在本机 localStorage）。面板显示姿态帧率、肩点可见度与缺失原因、q / minQ、站立晃动、蹲位时长、检查项、u 刻度（站 / 保 / 蹲 / A）、基线修正、本轮峰值、蓄力与释放方式。
「导出日志」下载最近 3000 帧的数值日志 JSON（只含数值，不含画面），`window.__g05debug` 也可直接读取。
`localStorage yukee.poseDelegate=CPU` 可强制 MediaPipe 走 CPU（排查 GPU 推理问题 / 无 GPU 环境）。

## 玩法
- 等轴 2.5D 悬浮方块（标准方块 / 窄方块 / 圆柱），路线在左上、右上两个方向交错，不会连续三次同向。
- 蓄力越久跳得越远，最大蓄力 1.5 秒。落点按真实距离计算，**不吸附**：
  - 落上目标台得 1 分；中心命中得 2 分，连续中心命中递增（+2、+4、+6…）；白色同心圈加分台额外 +5。
  - 跳得太轻仍在原台：不得分也不失败，可再蓄力。
  - 不够 / 过远掉落；踩到边缘会翻倒再掉落。
- 连续成功 5 次通关；失败显示结算，可「再来一局」（按钮或 Enter）或「结束活动」。
- 画面：浅灰背景、柔和粉彩方块（顶面、两侧明暗、远处投影）、白色小机器人（深色面屏 + 青色眼睛 + 薄荷天线点）。
  蓄力时机器人与平台同时压缩、脚下细小光点收拢；空翻抛物线、落地回弹、中心命中白色涟漪与「完美 +N」、镜头弹簧跟随。
- 文件：`src/games/squatJump/jumpLogic.ts`（纯逻辑）、`squatJumpScene.ts`（Canvas 绘制与动画）、`SquatJump.tsx`（控制器 + HUD）、
  `SquatCalibrationView.tsx`（校准）、`squatJump.css`。

## 输入
键盘与摄像头只是两种「按下 / 松开」来源，共用同一个控制器与 `JumpRun.jump(chargeSec)`。

**键盘演示**（校准页「键盘演示 · keyboard_demo」）：按住空格蓄力、松开起跳；Esc 暂停（暂停会清空蓄力）。
页面标注 `keyboard_demo · 非人体识别`，结果写明「不计入真实活动」，状态机只记录来源、不增加完成次数。

**摄像头浅蹲**（`src/vision/squatPose.ts`，依据《电脑端动作游戏完整交互与设计方案 10.21 V2》第 17–19 节）：
- 只读 MediaPipe 左右肩（11 / 12）的**图像坐标**，可见度 ≥ 0.65；不使用以髋为原点的世界坐标（会抵消整体下降）。
- 校准：站直 2 秒（双肩起点、肩宽 W0、静止抖动）→ 舒适浅蹲并停住约 0.5 秒（本人幅度 A，最小有效下降 max(12px, 6×抖动, 0.08 W0)）→ 站回。
- `q = ((L.y−L0.y)+(R.y−R0.y)) / 2 / W0`，`u = q / A`。
- 进入蓄力：先在站立区（u ≤ 0.2）累计 200ms，再 u ≥ 0.65 且检查项通过并稳定 0.3 秒。保持在蹲位（u ≥ 0.5）期间蓄力增长；回升途中冻结；
  回到 u ≤ 0.25 稳定 0.22 秒才释放起跳。抖动跨过单一阈值不会反复触发；保持浅蹲不会重复起跳。
- 检查项：两肩同步（位移差 ≤ 0.3A）、肩宽 0.8–1.2 W0（前探暂停）、横移 ≤ 0.25 W0、肩线侧倾 ≤ 10°。蓄力中检查失败则取消本轮、不起跳。
- 丢失双肩：< 0.3 秒冻结输入、不误释放；> 0.3 秒取消本轮并提示，回到站立区稳定约 1 秒后恢复。
- 落地后需要先站直才能开始下一次蓄力。

**限制**：这些阈值是展前起测值；沙箱只用合成关键点（单元测试）和无人画面的假摄像头验证过，**没有真人摄像头验证**。
只看双肩无法严格区分浅蹲与弯腰，正面单摄像头也不能评估膝关节动作质量。
