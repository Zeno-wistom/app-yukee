# 云端拾光 · Cloud Hop

Processing 4 / Java 模式的桌面体感应用。第一张界面按照 Figma 的 `Android Expanded - 7` 设计：左侧显示日期、时间、日常安排与心情，中间是机器人伙伴表情，右侧提供喝水、灯光、声音、游戏和提醒入口。“GAME TIME / 动一动”进入像素跳台游戏。

## 启动

**本机最快方式：双击 `启动游戏.bat`。** 脚本会使用已安装的 `C:\Program Files\Processing` 编译并运行。不要单独移动该文件；请保留整个 CloudHop 文件夹。

也可以在 Processing 中打开 `CloudHop.pde`，选择 Java 模式，点击运行。其余 `.pde` 文件会作为同一草图的标签页加载。游戏不需要另装 Processing 扩展库。

初始窗口为 1600 × 320，可以拖动调整大小，画面保持 Figma 原型的 **2000 × 400（5:1）横向比例**并等比缩放。

## 交互流程

启动后进入机器人伙伴首页：

1. 点击 **GAME TIME / 动一动**，进入横向游戏卡片选择。
2. 点击中央的“云端拾光”卡片，查看游戏说明。
3. 点击 **START / 开始**，选择继续存档或新游戏。
4. 新游戏会使用三个本机存档位置中的空位；三个位置均满时，必须明确选择并确认覆盖。
5. 继续游戏会打开存档列表。删除记录前会再次确认，删除后可在底部提示中撤销。
6. 进入摄像头准备页，完成校准后开始三秒倒计时。
7. 游戏过程中点击右上角暂停；退出前会保存，并可在下次继续。

首页功能：

- **DAILY ROUTINE**：查看喝水、运动和心情三项日常进度。
- **EMOTION**：主动记录“很放松 / 很专注 / 有点累”，机器人表情与文案会随之变化。
- **DRINK TIME**：记录喝水次数并设置 30、45 或 60 分钟的应用内提醒。
- **LIGHT**：调整机器人表情屏幕的亮度和暖光 / 清光。
- **SOUND**：调整点击、金币和提醒音效，默认静音。
- **WEAK / STRONG HINT**：切换底部轻提示或明显弹窗提醒。
- **电源按钮**：进入休息模式或关闭应用。关闭前保存游戏进度。

## 摄像头操作

1. 从首页进入“云端拾光”，新建或继续一段冒险，在摄像头准备页点击“开启 / 校准摄像头”。它会打开本地识别页面，推荐使用 Chrome 或 Edge。
2. 在识别页面再次点击“开启摄像头”，允许浏览器使用摄像头。
3. 按提示依次完成：**正脸保持约 1.5 秒 → 向自己的左侧转头 → 正脸 → 抬头 → 正脸**。程序会学习方向，避免镜像造成左右颠倒。
4. 页面显示“已就绪”后，切回游戏，点击“开始冒险”。
5. **请保持识别页面打开，推荐与游戏并排显示。** 浏览器可能对完全隐藏的页面降频；超过 0.8 秒没有新识别结果，游戏会暂停。重新识别后点击“继续冒险”。

| 动作 | 游戏反应 |
| --- | --- |
| 头部向左转 | 角色持续向左移动 |
| 头部向右转 | 角色持续向右移动 |
| 回到正脸 | 停止横向移动 |
| 抬头 | 起跳一次 |
| 抬头后回正 | 为下一次跳跃准备 |
| 低头 | 不触发额外游戏动作 |
| 人脸丢失或摄像头断开 | 自动暂停，保留当前进度 |

页面中可调整左右转头和抬头的角度阈值。如果动作不易触发，可稍微调低；误触较多可调高。改变坐姿或镜头位置后，点击“重新校准”。

**识别在本机完成。** 模型、识别运行库已下载到 `data/tracker/vendor`，运行时不依赖外网。浏览器仅向本机游戏发送方向、跳跃序号、是否识别到人脸等状态，不发送或保存摄像头画面。

## 玩法

- 共有 20 层台阶、40 枚金币，每枚金币 10 分。
- 第 5、10、15、20 层会点亮检查点。
- 掉落后回到最近检查点，已收集的金币保留。
- 到达第 20 层即通关，获得“云端探险家”奖励及 100 分登顶奖励。
- 最高金币数保存在 `record.json`。三个游戏存档、首页设置与日常状态保存在 `companion.json`。
- 游戏每两秒、暂停和退出时自动保存。存档包含角色位置、金币、最高层、检查点和通关状态。

## 键盘体验

摄像头准备页点击“暂用键盘体验”，或按 K 进入键盘模式。

| 按键 | 功能 |
| --- | --- |
| ← / A、→ / D | 左右移动 |
| 空格 / ↑ | 跳跃 |
| P | 暂停 / 继续 |
| Esc | 暂停 |
| C | 打开摄像头设置页面 |
| K | 切换为键盘体验 |
| Tab、Enter | 切换并激活界面按钮 |

关闭游戏使用窗口右上角的关闭按钮。摄像头页面可以单独点击“关闭摄像头”或关闭浏览器标签页。

## 文件说明

- `CloudHop.pde`：Processing 窗口、像素绘制、界面和操作。
- `Game.pde`：平台、重力、碰撞、金币、检查点和通关逻辑。
- `CameraBridge.pde`：仅监听本机的摄像头状态连接。
- `Interface.pde`、`FlowScreens.pde`：Figma 首页、游戏卡片、弹窗和流程界面。
- `Navigation.pde`：页面跳转、返回、取消、确认和退出行为。
- `LocalStore.pde`：三格存档、设置、日常状态和音效。
- `data/tracker/`：摄像头页面、头部姿态控制和本地识别模型。
- `data/ui/`：从 Figma 原型下载的电源、返回、方向、播放和暂停图标。
- `checks/v2/`：各个关键界面的实际运行截图。
- `tools/build.ps1`：使用本机 Processing 自带 JDK 编译和运行。
- `tools/check.ps1`、`checks/`：玩法、连接和动作转换验证。
- `tools/download-camera.ps1`：如模型文件丢失，可联网重新下载。

## 已完成的验证与限制

已在本机 Processing 4.5.6 自带 Java 17 环境编译，并启动窗口检查主要页面。自动测试覆盖全部 20 层连续跳跃、通关、检查点、金币只计一次、掉落恢复、单向平台、人脸失联超时、姿态校准和跳跃防重复；还覆盖页面跳转、摄像头入口限制、暂停保存、退出取消、精确恢复、三格存档保护、删除撤销和设置重启恢复。浏览器中已用空白画面验证本地 MediaPipe WASM 和模型能完成推理。

**尚未进行真人摄像头动作实测。** 实际左右转头、抬头灵敏度及不同光线下的识别稳定性，需要使用者完成校准后验证。此版本有简短界面与奖励音效，默认静音；没有背景音乐或敌人。Figma 中其余“跳蹲、腕部、扭腰”游戏已保留卡片和介绍占位，具体玩法尚未定义，因此不会进入空白游戏。

## 依赖来源

游戏角色及环境由代码绘制，没有使用马里奥品牌素材。

人脸识别使用 Google MediaPipe Tasks Vision 0.10.32 与 Face Landmarker 模型。开发接口参考：[Google 官方 Face Landmarker Web 文档](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)。运行库来源为 npm 官方包的 jsDelivr 镜像，模型来源为 Google 官方模型存储；详见下载脚本与 `THIRD_PARTY.md`。
